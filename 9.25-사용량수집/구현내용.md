## 구현 함수와 모델

### `MemoryUsageSample`

- `elapsed_ms`: 실행 시작 이후 monotonic 경과 시간
- `memory_bytes`: 해당 시점의 cgroup `memory.current`

### `MemoryUsageSampler`

- `sample_if_due(now)`: 100ms 경계마다 현재 메모리를 수집한다.
- `sample_final(finished_at, final_memory_bytes)`: 종료 시 마지막 샘플을 추가한다.
- 읽기 실패 또는 예외는 해당 샘플만 건너뛰며 실행 판정에 영향을 주지 않는다.

### Wall Time

기존 execution loop의 start gate 해제 직전 `time.monotonic()` 값과 container
종료 시각의 차이로 `wall_time_ms`를 계산한다. TIME_LIMIT 판정과
SIGSEGV/TIME_LIMIT 경쟁 처리 로직은 변경하지 않았다.

## 데이터 흐름

```text
execution cgroup memory.current
        ↓
MemoryUsageSampler (100ms, monotonic)
        ↓
MemoryUsageSample[] + wall_time_ms
        ↓
ExecutionResult
        ↓
Runner ResourceUsage
        ↓
Backend RunnerResponse
        ↓
ExecutionService
        ↓
DB memory_usage_samples JSON + wall_time_ms
        ↓
실행 조회 API
```

`memory_peak_bytes`는 기존 `memory.peak` 값을 계속 사용한다. 시계열 최대값으로
대체하지 않는다.

## API 구조

```json
{
  "resource_usage": {
    "wall_time_ms": 1537,
    "memory_peak_bytes": 52428800,
    "memory_usage_samples": [
      {
        "elapsed_ms": 100,
        "memory_bytes": 12582912
      }
    ]
  }
}
```

별도 Wall Time 시계열은 저장하지 않는다. `memory_usage_samples[].elapsed_ms`가
그래프의 X축이고 `wall_time_ms`가 최종 실행시간이다.

## DB 주의사항

현재 Backend는 Alembic 같은 migration 도구 없이 `Base.metadata.create_all()`을
사용한다. 새 DB에는 `memory_usage_samples`가 생성되지만 기존 DB 테이블에는
새 컬럼이 자동 추가되지 않으므로 배포 시 운영 DB 스키마 반영이 필요하다.
